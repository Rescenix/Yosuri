## 三、关键耦合点（移植需要关注）

### 3.1 重度耦合：浏览器 Web API

| API | 使用位置 | 对 Android 移植的影响 |
|-----|---------|----------------------|
| **`page-flip` (npm 包)** | `usePageFlip.js` | 需要 Canvas/DOM 3D 变换，Android WebView 可运行，但性能可能下降 |
| **`Range` / `Selection`** | `useAnnotation.js`, `useMobileSelection.js` | 用户选择文本并高亮，WebView 可用，但 `highlightText()` 直接操作 DOM |
| **`IndexedDB`** | `cachePagination.js` | 分页缓存存储在浏览器，Android 端需要确保 WebView 的 IndexedDB 开启（默认有） |
| **`localStorage`** | 几乎全部 composable | 阅读进度、书签、笔记全在 localStorage，Android 端需使用同一 WebView 实例 |
| **`Web Worker`** | `pagination.worker.js`, `usePageFlip.js` | Worker 在 Android WebView 受支持，但低版本可能有限制 |
| **`fetch()`** | 多处 | 需要 Android 端提供 `/api/chat`, `/api/book/*`, `/api/image/generate` 的对应端点 |

### 3.2 中度耦合：DOM 尺寸依赖

- `ExactPaginator.js` 中的 `exactPaginate()` 依赖于 `pageWidth` 和 `pageHeight`，这些尺寸来自 **`flipContainerRef` 的 `clientWidth/clientHeight`**。
- 如果在非浏览器环境调用排版函数，需要手动传入宽高值。
- `useMobileReader.js` 同样依赖 DOM 尺寸进行流式排版。

### 3.3 轻度耦合：跨模块共享状态

- `useAnnotation.js` 与 `SidePanel.vue` 通过 `localStorage` + 自定义事件 (`annotations-updated`) 共享批注数据。
- `useMobileSelection.js` 通过回调注入（`generateComment`, `showResultCard`, `highlightText`）与 `useAnnotation.js` 交互；其声明文件在 `../composables/`，脱离了 reading 目录。
- `EmotionGlow.vue` 依赖 `../shanxi/composables/useEmotion.js`，属于跨模块调用。

## 五、移植到 Android Assets 的策略建议

### 策略 A：整体 WebView 嵌入（推荐）

将整个 reading 模块以 WebView 形式嵌入 Android，优点是不改代码、快速上线。

**需要 Android 侧配合：**

1. **JsBridge 提供 API 端点**
   - `GET /api/book/content?bookId=xxx` → Android 读取本地文件返回
   - `POST /api/chat` → Android 调用 AI 接口
   - `POST /api/image/generate` → Android 调用绘图接口
   - `GET /api/book/list` → 返回本地书籍列表

2. **保持 WebView 实例持久化**（换书时不要销毁）
   - `localStorage` 中的数据（进度、书签、笔记）依赖同一 WebView 实例
   - 或者通过 JsBridge 同步 localStorage 到 Android

3. **开启 WebView 功能**
   ```java
   webView.getSettings().setJavaScriptEnabled(true);
   webView.getSettings().setDomStorageEnabled(true);    // localStorage
   webView.getSettings().setDatabaseEnabled(true);      // IndexedDB
   webView.getSettings().setAllowFileAccess(true);
   ```

### 策略 B：剥离为纯 HTML + JS 资源包

如果需要离线运行，可将 reading 模块构建为独立 bundle：

**需要剥离的浏览器依赖：**
- `page-flip` → 检查是否有纯 CSS/Canvas 替代方案，或保留经测试其能在 Android WebView 正常运行
- `@chenglou/pretext` → 保留（纯 JS 计算）
- Worker → 保留（Android 7+ 支持）

**需要注入的 Android API 桥接：**
- 在 `window` 上注入 `androidGetBookText(bookId)` 替代 fetch
- 在 `window` 上注入 `androidChat(message)` 替代 `/api/chat`

### 策略 C：仅复用排版引擎

如果只需要文本分页能力，可以只提取 `ExactPaginator.js` + `cachePagination.js`（或替换为 Android Room 存储），在 Android 原生端运行排版。

**提取范围：**
- `ExactPaginator.js`（纯 JS，无 DOM 依赖，但需传入 `pageWidth/pageHeight`）
- `cachePagination.js`（可替换为 Android 端的缓存实现）
- 注意：`pagination.worker.js` 使用 Worker，Android 端需使用 `loadUrl("javascript:...")` 或替换为纯同步调用

## 六、总结

- **核心值钱资产**：`ExactPaginator.js`（精确中文排版）和 `useAnnotation.js`（AI 批注交互流）
- **最大耦合点**：`page-flip` 3D 翻页库（桌面专属）和 DOM Selection API（批注系统）
- **推荐策略**：策略 A（整体 WebView 嵌入），因为该模块与浏览器 API 深度绑定（DOM、IndexedDB、Worker），分离成本高；WebView 是目前最好的容器。
